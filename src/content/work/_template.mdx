# A NOTE ON NAMING PROPERTIES
# Describe the arrival state factually and neutrally. "Forty recertifications
# past due" is a fact. "Failing property" is a characterization of somebody
# else's asset on a public page that search engines will index. If in doubt,
# describe the property by type and size rather than by name.

title: Case study title
summary: One line that says what this was and what changed. Shown in the list.

# This block sits at the head of the jacket and reads like an audit summary
# line. Three or four entries works best.
metrics:
  - value: "000"
    label: Units
  - value: "00%"
    label: Occupancy
  - value: "0 months"
    label: Duration

# The three-part structure below is how this work actually gets assessed, so
# it stays. Keep each one to a short paragraph.
situation: >-
  What was true on arrival. Factual and neutral. Counts, dates, what was
  outstanding.
action: >-
  What you did, in order. Plain verbs, active voice, first person.
outcome: >-
  What changed, with the numbers attached and the time it took.

date: "2026-01-01"
order: 0
draft: false
---

The narrative goes here, beneath the metrics block. This is the long version:
what you found, what you tried, what worked. Write it in first person.

Section breaks are a short centered rule rather than a bold heading, so the
page keeps reading as one document.
